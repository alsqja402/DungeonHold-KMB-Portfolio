# 문제 해결과 현재 한계

[README](../README.md)

## 1. 빠른 적이 목표 근처에서 영구 정지

**증상:** Stage 3에서 빠른 적이 경로 끝 근처에 멈추고 뒤따르는 적이 몰렸습니다.

**근거:** 도착 허용 거리 0.1에 대해 수평 거리 0.009, 높이 차이 약 0.217이 기록됐습니다. 다른 로그에서는 수평 0.004인데 남은 경로 거리 0.101로 판정됐습니다. 경로 소진 후 오류 처리로 이동이 중단됐습니다.

**수정:** [EnemyMovement](../src/Enemy/EnemyMovement.cs)에서 계산된 NavMesh 경로의 마지막 코너를 도착 기준으로 사용하고, 완전한 경로를 소진한 경우 수평 도착 조건으로 진행하도록 했습니다.

```cs
bool hasArrived =
    (remainingDistance <= _arrivalDistance || !_navMeshAgent.hasPath) &&
    distanceToWaypoint <= _arrivalDistance;
```

이 코드는 활성 NavMesh·경로 대기·완전한 경로 검사를 통과한 뒤 실행됩니다. 경로가 없다는 이유만으로 먼 웨이포인트를 건너뛰지는 않습니다.

첫 보완에 3차원 거리 검사가 남아 재발했고, 추가 로그를 보고 보완했습니다. 코드 반영과 전체 경로 재검증 완료는 구분합니다. 군집 정체가 모두 이 원인이라는 결론도 내리지 않았습니다.

## 2. 준비 중 보스가 먼저 등장

씬 경과 시간과 전투 시간을 구분하지 않으면 설치·재정비 중에도 전환할 수 있습니다. [Stage3Controller](../src/Stage/Stage3Controller.cs)에서 시간 누적·시간 전환의 전투 상태와 지정 웨이브 도달을 검사하도록 했습니다. 목표 파괴 전환은 유지하고, 보스만 남은 구간에서도 전체 제한시간은 진행합니다.

## 3. 생성 실패 후 셀과 재화가 남는 문제 방지

[BuildPlacementController](../src/Installation/BuildPlacementController.cs)에서 점유·소비·생성 성공 여부를 따로 추적합니다. 실패 시 생성물과 점유를 정리하고 실제 차감분만 원래 도전에 복구합니다. 프리뷰의 성공 표시를 실제 설치 승인으로 쓰지 않습니다.

## 4. 첫 전투 시작이 InvalidPosition으로 거절됨

WaveController가 공용 BeginCombat을 호출할 때 미배치 고용 동료의 생성 위치를 찾지 못하면 InvalidPosition이 반환됩니다. 공용 위치 탐색은 NavMesh와 공간 조건을 검사합니다.

현재 WaveController는 이 실패를 웨이브 중단으로 처리합니다. 준비 상태 유지·이동 후 재시도·화면 안내는 공통 담당자와 협의할 후속입니다. 동료 위치 탐색 코드는 이 저장소에 포함하지 않았으며 해결 완료로 기록하지 않습니다.

## 5. 성능 마커를 원인으로 오인하지 않기

Shadows.Prepare 아래에서 15ms가 보였지만 실제 하위 항목은 에디터의 MaterialEditor 처리였습니다. 보스 등장 프레임은 게임 내 파편 생성, 다른 139ms 피크는 EditorLoop가 주된 비용이었습니다. [성능 문서](06-performance.md)처럼 부모 이름보다 하위 호출과 실제 측정 범위를 확인했습니다.

## 확인 범위

이 발췌 저장소에서는 원본 Unity 씬·팀 공통 코드·에셋이 없어 실행하지 않았습니다. 원본 프로젝트의 사용자 플레이와 로그, 코드 검사, 재확인 대기 상태를 사례별로 구분했습니다. 자동 테스트 통과나 모든 예외의 해결을 주장하지 않습니다.
